# PerturBench Norman19: beat the published best combination-perturbation prediction metrics (CRISPR Perturb-seq in a leukemia line)

# Overview

> Bank id `perturbench-norman19-combo-prediction` · harvest · tractability 3 · laptop-hours · disclosure **open**
> Bank says open as of 2026-10-15. Statuses go stale — re-check the primary source before any work.

## Statement

PerturBench (Altos Labs; NeurIPS 2025 Datasets and Benchmarks; arXiv 2408.10609v4, last updated 2025-10-24) is a standardised framework for single-cell perturbation-response prediction with public datasets, fixed splits, a published metric suite and an Evaluator class. The Norman19 task is combination prediction in the K562 chronic-myelogenous-leukemia line: train on all single CRISPRa perturbations plus 30% of dual perturbations, predict the held-out 70% of dual perturbations. The published Table 3 (arXiv v4) is the public scoreboard: best cosine logFC 0.79 +/- 0.01 (LA, with SAMS-VAE (S) 0.78 and CPA* (noAdv) 0.77), best cosine-logFC rank 0.005 +/- 0.002 (LA; lower is better, 0 perfect, 0.5 random; CPA* (noAdv) 0.0057), best MMD PCA 0.74 +/- 0.05 (SAMS-VAE (S)), best DEG recall 0.032 +/- 0.004 (CPA*). The authors themselves report that several published models suffer mode collapse and that simple models (a latent-additive model, a linear model) are competitive - a strong hint that the frontier is soft. All processed data and splits are public and ungated on Hugging Face (altoslabs/perturbench, last modified 2025-10-21; norman19_processed.h5ad.gz plus split tarballs), the Norman19 splits are generated by the package itself, and the metrics ship in the repo (pushed 2026-08-10). Norman19 is a few GB of sparse counts: CPU-feasible for linear/latent-additive/kernel models, which are precisely the models that currently lead.

## Success criterion

Success means a model trained with PerturBench's own data accessors and PerturBench-generated Norman19 combo splits (train = all singles + 30% duals; evaluate on the held-out duals), scored by the repo's own Evaluator class at a pinned commit, that strictly beats the best published value for at least ONE of the four metrics in the latest arXiv version of PerturBench Table 3 (re-fetched live immediately before claiming; direction per metric as recorded above) by at least 3x the published standard deviation of the previous best AND by a margin that survives 5 independent seeds reported as mean +/- std, while not being worse than the previous best on ANY other reported metric by more than 1 published std (so that mode collapse or metric gaming is excluded). Deliverables: pinned perturbench commit, dataset file sha256s from the Hugging Face repo, the split files actually used, the training script and config, the Evaluator output for all four metrics over 5 seeds, and the same Evaluator run on the published LA and Linear baselines in the same environment and splits (whose values must land within 1 published std of Table 3, or the comparison is void). No held-out dual perturbation's measured expression may be used in training, model selection, early stopping, gene filtering, normalisation or the HPO objective.

## Verification

Skeptic creates a clean venv, installs perturbench at the attacker's pinned commit, downloads norman19_processed.h5ad.gz from the Hugging Face repo and compares sha256 with the attacker's manifest, regenerates the splits with the package (or loads the attacker's split files and verifies they match the package's generator and that train/test dual perturbations are disjoint), loads the attacker's predicted anndata objects, and runs the repo's Evaluator to recompute all four metrics (minutes to an hour). Then re-trains the attacker's model for at least 2 of the 5 seeds (laptop-hours) to confirm the metric range, and re-runs the LA and Linear baselines in the same environment to confirm the published values are reproduced. Leakage audit: assert that no held-out dual perturbation appears in training, that highly-variable-gene selection and normalisation statistics were computed on training cells only, and that the HPO objective never read test cells.

## Angles

- Conventional: strengthen the latent-additive baseline that currently leads - per-perturbation latent offsets with shrinkage toward a learned low-rank basis of single-perturbation effects, plus an explicit learned interaction term for pairs (the whole task is predicting the non-additive part).
- Conventional: train directly for the reported metrics (cosine on logFC and the rank metric) rather than for reconstruction RMSE; the published HPO objective is RMSE + 0.1 x RMSE-rank, which is not what Table 3's headline columns measure.
- Cross-domain import (coding theory / superimposed codes): single perturbations are codewords and a dual perturbation is their superposition through a non-linear channel. Fit a decoder for the interaction residual using ideas from multi-user detection / successive interference cancellation: subtract the predicted additive part, then decode the residual against a dictionary of interaction motifs learned from the 30% observed duals.
- Cross-domain import (statistical physics): treat gene-expression responses as an Ising/Potts system with per-perturbation external fields and learn pairwise couplings between perturbation targets by pseudo-likelihood (the standard direct-coupling-analysis machinery). DCA is cheap, interpretable, CPU-only, and is precisely a tool for inferring pairwise interaction from single-and-pair observations.
- Cross-domain import (compression): choose the number of latent dimensions and the interaction sparsity by MDL / two-part code length on held-in cells rather than by validation loss, which is the standard defence against mode collapse (a collapsed model has a short code but terrible residual cost, and MDL sees that trade-off explicitly).
- Anti-collapse regularisation: explicitly penalise low variance across predicted perturbation profiles, or train with a rank-based (listwise) loss so that predicting the mean response is heavily penalised; the paper reports collapse in widely used models, so this alone may move the rank metric.

## Pitfalls

- Mode collapse that flatters the metrics: predicting the average perturbation response can give a respectable cosine logFC while the rank metric and DEG recall reveal nothing was learned. Any claim must report all four metrics and the collapse audit.
- Split regeneration mismatch: the Norman19 splits are generated by the package, so a different version or seed yields a different held-out set and incomparable numbers. The skeptic must verify the split generator and the exact held-out dual list.
- Control/leakage through preprocessing: computing HVG selection, size-factor normalisation, logFC reference means or gene filtering over ALL cells (including held-out duals) leaks the test distribution. logFC is computed against controls, and which control cells are used must be exactly the package's convention.
- Metric-definition drift: cosine logFC, the rank metric and DEG recall have specific definitions in the repo's Evaluator; recomputing them with the attacker's own code (different DEG cutoff, different number of top genes, different distance) is the easiest way to manufacture a fake record. Only the repo's Evaluator at a pinned commit counts.
- Comparing against a stale table: PerturBench has had four arXiv versions and the repo adds datasets; the published best for a metric must be re-read from the latest version and cross-checked against repo results before any claim.
- Single-seed wins: published stds are small (1e-3 to 1e-2) but seed-to-seed variation of a new model can be large; 5 seeds and a 3x-std margin are required.
